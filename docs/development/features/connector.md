# Claude and ChatGPT connector (MCP)

Money is also a remote MCP server: a user adds `https://<domain>/mcp` to Claude or ChatGPT, signs in to Money once and allows access, and the assistant can then read the book and (for editors and admins) add, change and delete transactions as that user. Money is its own OAuth 2.1 authorization server, so nothing is registered anywhere. The steps for users are on `/settings/connector`.

[Architecture](../architecture.md) explains how the pieces fit together; [conventions](../conventions.md) the rules for writing code.

## How it works

1. **Discovery:** Claude or ChatGPT calls `/mcp` without a token and gets 401 with a link to the protected-resource metadata, which names Money's authorization server (`/api/auth`).
2. **Client identity:** the client's `client_id` is a URL to its Client ID Metadata Document. Only documents on `https://claude.ai` and `https://chatgpt.com` are accepted, so nothing is registered and no look-alike app can connect.
3. **Sign-in and consent:** the browser opens Money's `/login`, then `/oauth/consent`, where the user allows access. Better Auth issues a signed JWT access token (an hour) and a refresh token.
4. **Each MCP request:** `src/mcp/auth.ts` verifies the token, then one SQL statement checks that the user still allows the app, isn't disabled, and reads their current role. Viewers get only the read tools.
5. **Tools** convert dates (the user's calendar) and amounts (the book currency's main unit) at the boundary, check the role again for writes, and call the same queries and rules as the web app.

## Endpoints

| Path                                               | What it is                                                                                                                                 |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `/mcp`                                             | The MCP endpoint (Streamable HTTP). Needs a bearer token; without one it answers 401 with `WWW-Authenticate: Bearer … resource_metadata=…` |
| `/.well-known/oauth-protected-resource/mcp`        | Protected resource metadata (RFC 9728): names the authorization server                                                                     |
| `/.well-known/oauth-authorization-server/api/auth` | Authorization server metadata (RFC 8414)                                                                                                   |
| `/api/auth/…`                                      | Better Auth's OAuth endpoints: authorize, token, consent (issuer `<app>/api/auth`)                                                         |
| `/login`, `/oauth/consent`                         | The pages the user sees while connecting                                                                                                   |
| `/settings/connector`                              | The connector URL, the steps for users and the connected apps (revoke)                                                                     |

Scopes: `money` (the MCP endpoint) and `offline_access` (refresh tokens). Grants: authorization code with PKCE (S256) and refresh token.

## Tools

All tools take and return JSON. Dates are in the user's calendar (Jalali `YYYY/MM/DD` or Gregorian `YYYY-MM-DD`; input in either, the year decides). Amounts are in the book currency's main unit: whole rials for IRR, up to two decimals otherwise. Limits are in `src/constants/connector.ts`.

| Tool                  | Who             | Input                                                                                                                                                                          | Returns                                                                                                                                                                                |
| --------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `today`               | everyone        | nothing                                                                                                                                                                        | Today's date, weekday, calendar and date format, time zone, currency and amount unit, and the user's name, language, role and `can_write`                                              |
| `list_accounts`       | everyone        | nothing                                                                                                                                                                        | Accounts in the user's order with id, name, type, masked identifier, balance and `archived`; the total balance of the active ones                                                      |
| `list_categories`     | everyone        | nothing                                                                                                                                                                        | Expense and income categories with their subcategories, ids and `archived`                                                                                                             |
| `list_transactions`   | everyone        | Optional `from`, `to`, `types`, `account_id`, `category_id`, `tag`, `search`, `unknown_only`, `limit` (default 100, at most 500), `cursor`                                     | The count and income and expense totals of **every** match, the listed transactions (newest first; `unknown: true` without a category), their tags and `next_cursor` for the next page |
| `add_transactions`    | editors, admins | `transactions`: 1 to 100 items with `type`, `date`, `amount`, `account_id`, optional `to_account_id` (transfers), `category_id` (left out when unknown), `description`, `tags` | All saved or none. The saved transactions with their ids, and stored transactions with the same date, account, amount and type as possible duplicates                                  |
| `update_transaction`  | editors, admins | `id` and only the fields to change                                                                                                                                             | `updated`: the transaction as saved                                                                                                                                                    |
| `delete_transactions` | editors, admins | `ids`: 1 to 100                                                                                                                                                                | `deleted` (the removed transactions) and `not_found` (ids that matched nothing). Marked destructive, so clients ask first                                                              |

**Errors** come back as tool results with `isError: true` and a JSON `{ "error": … }` in English, naming each problem (for example a date that isn't real, an archived account, a category of the other type, with the tool to look it up), so the model can fix the call and retry. The texts are `ERRORS` in `src/mcp/tools.ts`. The write tools read the role again on every call: a user demoted while connected loses them at once.

## Testing the connector

- **Locally** the connector URL is `http://localhost:3000/mcp` (OAuth accepts plain HTTP only for `localhost`), while the app itself runs on `money.localhost`. claude.ai can't reach a local server; use an MCP client on the same machine (Claude Code, or the MCP Inspector with a client registered for it).
- **Preview deployments** use their branch URL: `https://<project>-git-<branch>-<team>.vercel.app/mcp`. Vercel's deployment protection must allow the request, or claude.ai can't reach it.
- **ChatGPT** can only reach a public HTTPS URL, not `localhost`. On a preview, Vercel’s deployment protection must let it through; otherwise ChatGPT reports that the server does not implement OAuth.
- **Claude Code** can connect to a local or preview server as an MCP client, which is the quickest way to try a tool change.

## Details

Users add `https://<domain>/mcp` in Claude (Settings → Connectors → Add custom connector), sign in to Money once and allow access; Claude then works on the shared book as that user, with that user's role. The URL and the steps are on `/settings/connector` (and in the README).

- **Authorization server:** Better Auth's `mcp` plugin (the OAuth 2.1 provider, `@better-auth/mcp`), with `cimd` (`@better-auth/cimd`): Claude identifies itself with a Client ID Metadata Document (its `client_id` is a URL Money fetches), which claude.ai prefers when the metadata advertises it. There is no open dynamic client registration, and no one creates clients through the API (`clientPrivileges: () => false`). **Only Claude and ChatGPT may connect:** a `client_id` URL must be on `https://claude.ai` (Claude, Claude Code) or `https://chatgpt.com` (`MCP_CLIENT_ORIGINS`, `isAllowedMcpClient` in `src/helpers/connector.ts`). Others are refused before their document is fetched (`cimd`'s `isMetadataDocumentUrlAllowed`), so a look-alike app can't show itself as «Claude» on the consent page; a `client_id` that isn't a URL can only have been added to the database by hand and is trusted. PKCE (S256) is required. Scopes: `money` (the MCP endpoint) and `offline_access` (refresh tokens); grants: authorization code and refresh token. The `jwt` plugin signs access tokens (its `/token` endpoint is in `disabledPaths`).
- **ChatGPT** connects to the same endpoint with no extra code: it uses a Client ID Metadata Document too (`https://chatgpt.com/oauth/client.json`, `private_key_jwt` with its published JWKS, redirect `https://chatgpt.com/connector_platform_oauth_redirect`), sends `resource`, uses PKCE S256 and expects the issuer parameter (RFC 9207), all of which the authorization server already provides. The steps are on `/settings/connector` and in the README. Its connections show in the connected apps list under the name from its metadata document; write-tool access still follows the user's role.
- **URLs** (`src/auth/urls.ts`): the app's URL is `BETTER_AUTH_URL`; without it, in Vercel production `https://$VERCEL_PROJECT_PRODUCTION_URL` (the shortest custom domain, otherwise the vercel.app one; a domain added later applies from the next deployment, `getVercelProductionHost`) and on previews `https://$VERCEL_BRANCH_URL` (connect a preview through its branch URL). The MCP resource is `<app>/mcp` (locally `http://localhost:3000/mcp`: over plain HTTP only `localhost` is accepted, so `money.localhost` becomes `localhost`). The issuer is `<app>/api/auth`.
- **Discovery:** `/mcp` answers unauthenticated requests with 401 and `WWW-Authenticate: Bearer … resource_metadata=…`. `/.well-known/oauth-protected-resource/mcp` (RFC 9728) and `/.well-known/oauth-authorization-server/api/auth` (RFC 8414) are route handlers (`src/app/.well-known/`), with CORS for browser-based clients. The proxy leaves `/mcp` and `/.well-known/` alone.
- **Sign-in and consent:** Better Auth sends the browser to `/login` with a signed authorization request; the login page shows «Claude is asking to connect» and posts the request (`oauth_query`) with the sign-in, and Better Auth continues to `/oauth/consent` (`ConnectorConsent`, outside the app shell). The consent page shows who is signed in («تغییر حساب» signs out and back in), what Claude may do (follows the role: viewers read only) and where the answer goes, and posts the answer to `/api/auth/oauth2/consent`. `readOAuthRequest` (`src/auth/oauth.ts`) checks the request's signature for both pages. An existing consent skips the page.
- **MCP endpoint** (`src/app/mcp/route.ts`): `mcp-handler`'s `withMcpAuth` with `verifyMcpToken` (`src/mcp/auth.ts`): the JWT is verified with the signing keys read through `auth.api.getJwks()` (not over HTTP), for this issuer and audience; DPoP-bound tokens and tokens issued to an app that may not connect (`isAllowedMcpClient` on `azp`) are refused. Then `checkMcpGrant` (`src/db/connector.ts`) checks in one statement that the user still allows the app (`oauth_consent`), marks it used (`last_used_at`, Money's own column) and reads the user fresh; banned users are refused. So revoking, disabling and a password reset or change take effect on the next request, although access tokens are self-contained JWTs (an hour), and a role change applies right away.
- **Tools** (`src/mcp/tools.ts`, server instructions in `src/mcp/instructions.ts`, server built per request in `src/mcp/handler.ts`): `today`, `list_accounts` (balances), `list_categories` (with subcategories), `list_transactions` (filters, totals of every match, cursor), and for editors and admins only `add_transactions` (up to 100, all or none, with possible duplicates: same date, account, amount and type), `update_transaction` and `delete_transactions` (destructive hint). Viewers don't get the write tools, and the write tools re-read the role on every call (the MCP equivalent of `requireWrite()`, which needs a session cookie). They reuse the `src/db` queries and `transactionSchema` / `checkTransactionReferences`; errors for Claude are English texts in the tools, not messages. Rows added get `source = "mcp"` (Claude) or `"chatgpt"` when the token's client is ChatGPT (its client_id starts with `https://chatgpt.com/`, `sourceForMcpClient`); `created_by` / `updated_by` are the token's user. Unknown transactions: Claude leaves `category_id` out when it can't tell the category (never «؟» in the description, which is optional); results mark them `unknown: true`, and `unknown_only` lists them. The description is the only free text: `add_transactions` and `update_transaction` still accept a `note` (described as deprecated) so a client that read the tool list before #133 keeps working, and add it to the end of the description with `withNote`; results have no note.
- **Dates and amounts at the boundary** (`src/helpers/connector.ts`): results use the user's calendar (Jalali `YYYY/MM/DD`, Gregorian `YYYY-MM-DD`). Input may be either: the year decides the calendar (below 1700 Jalali), so Claude copies a bank SMS date as it is and never converts calendars. Amounts are in the book currency's main unit (rials; dollars, euros, pounds with up to two decimals), converted to the stored smallest unit.
- **Time zone:** MCP requests have no browser, so `today` uses `user.time_zone`, which the app layout saves (after the response) when the browser's reported zone (TimeZoneSync's cookie) differs; otherwise Asia/Tehran.
- **Connected apps** (`/settings/connector`, `ConnectorSettings`): every role sees their own connections (`listConnections`: one per OAuth client, connected and last used days in the viewer's time zone) and can revoke one (`revokeConnection`: deletes its consent, refresh and access tokens in one statement).

## Libraries

- **MCP:** `mcp-handler` + `@modelcontextprotocol/server` (same as `daily-transactions`), behind OAuth bearer tokens issued by Better Auth (`@better-auth/mcp`, `@better-auth/cimd`, described above). `@better-auth/utils` is a direct dependency pinned to the version Better Auth's core expects, so the plugins share one copy of `@better-auth/core`.
