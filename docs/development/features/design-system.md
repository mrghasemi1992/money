# Design system and app shell

Money's look comes from design tokens (CSS variables) and a set of components in `src/components/ui/`, documented in Storybook ([money-storybook.vercel.app](https://money-storybook.vercel.app)). Every signed-in page sits in the app shell: a sidebar from 768px up, a top bar and a floating tab bar on phones.

[Architecture](../architecture.md) explains how the pieces fit together; [conventions](../conventions.md) the rules for writing code.

## Where the code is

| Part                     | Where                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| Tokens and global styles | `src/styles/tokens/`, `src/styles/base.css`, `src/styles/typography.css`, `src/styles/media.css`                    |
| Shared component styles  | `src/styles/control.module.css`, `menu.module.css`, `choice.module.css`, `list.module.css`                          |
| Components               | `src/components/ui/` (one folder each, with a story)                                                                |
| App shell                | `src/components/app-shell/`, `sidebar/`, `top-bar/`, `tab-bar/`, `more-menu/`, `user-menu/`, `navigation-progress/` |
| Navigation               | `src/constants/navigation.ts`, `src/helpers/navigation.ts`                                                          |
| Page building blocks     | `src/components/page-header/`, `page-skeleton/`, `page-status/`, `responsive-dialog/`, `confirm-dialog/`            |
| Fonts                    | `src/styles/fonts.ts`, `src/styles/fonts/`                                                                          |

## How it works

1. **Tokens** (CSS variables in `src/styles/tokens/`) hold every color, size, font and motion value. Dark mode re-points the semantic tokens under `[data-theme="dark"]`, set by an inline script before the first paint.
2. **Components** in `src/components/ui/` wrap Base UI parts and style them with CSS Modules through `data-*` state attributes. Logical CSS properties make every layout flip with `dir`.
3. **The app shell** wraps every signed-in page: sidebar (collapsible to an icon rail) from 768px up, top bar and floating tab bar on phones, the add-transaction form, the navigation progress bar and the toasts.
4. **Storybook** shows every component and page with sample data, with toolbars for theme, language, calendar and currency.

## Details

- **Brand:** name "Money": wordmark «پول» in the Persian interface (as in the old `money` project, now `money-old`), «Money» in the English one (`metadata.appName` message).
- **Look:** modern and calm, inspired by the Kanvas design system in Claude Design. Primary color is Kanvas royal blue `#223BB2` (`royal-600`), with a cool slate neutral tinted toward it and royal-tinted shadows. Flat stacked surfaces (page → card → raised), no gradients, no illustrations.
- **Logo:** Lucide's wallet glyph in white on a royal rounded tile, plus the wordmark («پول» / «Money») at weight 800. `Logo` and `LogoMark` in `src/components/ui/`, favicon in `src/app/icon.svg`, iOS icon in `src/app/apple-icon.tsx`.
- **Tokens** live in `src/styles/tokens/` and are the only source of colors, type, spacing, radius, shadows and motion:
  - Colors: raw ramps (`--royal-*`, `--slate-*`, accent hues) plus semantic aliases. Components use only the aliases: `--surface-*`, `--border-*`, `--text-*`, `--brand-*`, `--status-*`, `--amount-*`, `--budget-*`, `--cat-*`. Light on `:root` and `[data-theme="light"]`; `[data-theme="dark"]` re-points the aliases.
  - Type roles as `font` shorthands: `font: var(--type-body)` (`display`, `title-lg`, `title`, `heading`, `body-md`, `body`, `label`, `control`, `caption`, `eyebrow`, `amount-hero`, `amount-lg`, `amount`). 12px floor; never letter-space Persian. `:root:lang(en)` swaps `--font-sans` and `--font-features-tabular`, and the roles follow.
  - Categories: 10 hues + slate (`src/constants/category.ts`), each `--cat-<hue>` (dot), `-soft` (fill) and `-text` (label). A category is never shown by color alone. Its icon sits on its hue: a `-soft` tile with a `-text` icon (`CategoryChip` with `icon`, the categories list, `TransactionTile`), or the icon in `--cat` in menus and subcategory rows.
  - Focus is a 3px ring drawn with `box-shadow: var(--shadow-focus)` (danger controls: `--shadow-focus-danger`).
- **Fonts** (`src/styles/fonts.ts`, both variables on `<html>`):
  - Persian interface: Dana for everything (variable, `dana-variable.woff2`, copied from `daily-transactions`, `next/font/local`, `--font-dana`). Dana's default weight is 10 (hairline): every text style must set a weight. Declare `weight: "10 900"`.
  - English interface: Manrope (`next/font/google`, `--font-manrope`, variable weights 200–800), with Dana as the fallback for Persian text such as names and categories.
  - Tabular digits in amounts, dates and columns of numbers: `font-feature-settings: var(--font-features-tabular)` (helper class `.tabular`). It is `"ss03"` for Dana (no `tnum`) and `"tnum"` in English.
  - Never use Dana's `ss02` (it draws Latin digits as Persian glyphs and breaks copy and screen readers). Persian digits come from `Intl.NumberFormat("fa-IR")` (`formatNumber` in `src/utils/number.ts`).
- **Direction:** `<html lang dir>` follows the language (`fa` → `rtl`, `en` → `ltr`, `LOCALE_DIRECTIONS`), and Base UI's `DirectionProvider` (in `src/components/providers`) follows it for keyboard navigation and popup placement. Every layout must work in both directions. Use CSS logical properties only (`margin-inline-start`, `inset-inline-end`, `text-align: start`, …), never `left`/`right`. Where an element forces `direction: ltr` (number inputs), align it against the page's start edge with `:global(html[dir="rtl"])`.
  - Directional icons (back/forward arrows and chevrons) are written in LTR terms (`ChevronLeftIcon` = back) and get the global `mirror-rtl` class (`mirrorIcon` / `mirrorIcons` props on IconButton and Button), so they point the right way in either direction. Money-direction icons (`ArrowUpIcon`, `ArrowDownIcon`, `ArrowLeftRightIcon`) are direction-neutral and never mirrored.
- **Themes:** light and dark, both defined as tokens. Users choose light, dark or system (follow the OS) in settings only (`useThemePreference`, `setThemePreference` in `src/utils/theme.ts`; «system» clears the saved choice). No flash of the wrong theme on load (inline script in `<head>` sets `data-theme` from the saved choice, otherwise the OS setting), same setup as `orange`.
- **App shell** (`AppShell`, `src/components/app-shell`, rendered by `src/app/(app)/layout.tsx` around every signed-in page): a skip link to `#main`; from 768px up the `Sidebar` on the start side (logo, sections, `UserMenu`); on phones the `TopBar` (logo, back only on a subpage such as `/settings/connector`, to its section; the settings link, user menu) and the `TabBar`. Each part hides itself at the other breakpoint with CSS.
  - **Phone tabs:** a small capsule centred above the bottom edge (`--tabbar-*` tokens: 52px tall, inset from the sides and above the safe area; `--surface-floating`, see-through with a blur, solid without `backdrop-filter` or under `prefers-reduced-transparency`). It holds an icon per main page with `tab: true` (dashboard, transactions, reports; `getPhoneTabs`), each a 44px tap target named for screen readers by its `nav` label (no visible labels), then a «More» tab, and for editors and admins a divider and a small add button (a 36px royal circle, `--tabbar-add`; viewers get the tabs alone). The current page's icon is royal with a dot under it, so it reads without color. Pages and phone toasts keep `--tabbar-space` clear at the bottom. «More» (`MoreMenu`, `src/components/more-menu`, Base UI Menu) opens a small menu just above the capsule with a light dim (`--tabbar-scrim`; the capsule stays above it, and the ⋯ becomes ✕): links to the other sections except the top bar's settings (`topBar: true`; `getMoreItems`), so budgets, accounts, categories and user management, a line between nav groups, the current one royal with a dot; choosing one, tapping outside or the ✕ closes it. The «More» tab is marked while the current page is one of its sections. Four tabs at most; add a main page only by moving another behind «More».
  - The sections are `NAV_ITEMS` (`src/constants/navigation.ts`: label = `nav` message key, href, icon, `group`, `tab`, `topBar`, `adminOnly`), filtered by `getNavItems(role)` and marked active by `isNavItemActive` (`src/helpers/navigation.ts`, subpages count: `/settings/connector` → Settings). The sidebar lists three groups with a line between them (`group`: `main` = dashboard, transactions, budgets, reports, `book` = accounts and categories, `app` = settings and user management); the sections that aren't tabs or in the top bar are the «More» menu's links on phones. The layout passes the role from the user record; the pages check it again.
  - The sidebar collapses to an icon rail (tooltips show the labels). The choice is saved in `localStorage` (`money-sidebar`); an inline `<head>` script (`SIDEBAR_SCRIPT`) sets `<html data-sidebar="collapsed">` before the first paint, and CSS draws the rail from that attribute (`:global(html[data-sidebar="collapsed"])`), so it never flashes open. `useSidebarCollapsed` gives components the same value.
  - Add transaction: `AddTransactionProvider` (enabled for editors and admins) holds the form, a Dialog from 768px up and a Sheet on phones (`useMediaQuery(MOBILE_QUERY)`). `AddTransactionButton` goes in page headers (hidden on phones), the tab bar's add button opens the same form (`TransactionDialog`, see [transactions](transactions.md)).
  - Forms and confirmations opened from a page use `ResponsiveDialog` (`src/components/responsive-dialog`: a Dialog from 768px up, a Sheet on phones; `initialFocus` puts the focus on a form's first field) or `ConfirmDialog` (cancel plus one button that names the outcome).
  - Pages start with `PageHeader` (h1 title = the nav label, subtitle, actions; the dashboard's is the greeting). A subpage (`/settings/connector`, `/settings/import-export`) passes `back` (a link to its section, «‹ تنظیمات»), shown from 768px up; on phones the top bar has the back button. Each page's `loading.tsx` shows that page's skeleton (see Skeletons below; `PageSkeleton` only for a page without one), `error.tsx` `PageError` (retry), `not-found.tsx` `PageNotFound`, all inside the shell; the `[...rest]` catch-all sends unknown paths to that not-found page. Page titles are `<nav label> | پول` / `<nav label> | Money` (the root layout's title template).
- **Money semantics:** income and expense must be told apart by sign and wording too, not by color alone.
  - Income: green, `+`, ↓ `ArrowDownIcon`, «درآمد» / «Income». Expense: red, `−` (U+2212), ↑ `ArrowUpIcon`, «هزینه» / «Expense». Transfer: royal, no sign, ⇄ `ArrowLeftRightIcon`, «انتقال» / «Transfer». Balances: neutral text, `−` only when negative. The `Amount` component does all of this.
  - Numbers in amounts are an isolated left-to-right run (`<bdi dir="ltr">`). Persian: Persian digits, «٬» (U+066C) thousands, «٫» (U+066B) decimals, «٪» percent. English: Latin digits, «,», «.», «%».
  - Unit marks (`MONEY_UNIT_SYMBOLS`): Persian writes the unit's name after the number («۲٬۵۰۰٬۰۰۰ ریال», «… تومان», «… دلار», «… یورو», «… پوند»); English writes «$», «€», «£» before it, inside the left-to-right run, after the sign («−$1,234.56»), and «rial» / «toman» after it.
  - Budgets: ok (royal) → near the limit from 80% (amber, ⚠, «نزدیک به سقف») → over (red with diagonal stripes, «… بیش از بودجه»). `getBudgetStatus` in `src/helpers/budget.ts`.
- **Charts** (`BarList`, `ColumnChart`, `DataTable` in `src/components/ui/`; scale math in `src/utils/chart.ts`): every chart has a table view with the same figures (`ReportCard`).
  - `BarList`: ranked rows (label, `Amount`, share of the total, a bar as long as the row's part of the largest), the bar in the category's hue (`--cat-<hue>`) or brand royal. A row with sub-items is a button (`aria-expanded`) that opens them, each with its share of that row. Shares are written out, so bars are never the only reading.
  - `ColumnChart`: per month, income as a column rising from a zero line and expense as a column hanging below it (striped, so the two read without color), so the room between them is the month's result; a dot marks the net, and dashed lines the average month's income and expense (`partial` months, still running, left out). Columns are a CSS grid, so they flow in the page's direction; everything is positioned with CSS percentages, no SVG. The axis has round ticks without signs (`niceAxis` in about 6 steps) in a scale named under it (`moneyAxisScale`: «محور عمودی: میلیون ریال», "Axis: thousands of dollars"). Hover, tap or focus a month to read it above the plot (income, expense, net and savings rate; the other months step back while one is hovered); the columns are one tab stop (roving tabindex), arrow keys follow the reading direction, and each column's label reads its amounts. Labels thin to every other one when months crowd (container queries).
  - Sizes are `--chart-*`, `--bar-list-*` and `--report-*` tokens in `tokens/components.css`.
- **Dates in the UI** (`formatDate` in `src/utils/calendar.ts`, the `DateText` component): long «۹ مهر ۱۴۰۵» / «9 Mehr 1405» / «1 October 2026» (Persian Gregorian: «۱ اکتبر ۲۰۲۶»), weekday «پنج‌شنبه ۹ مهر ۱۴۰۵» / «Thursday, 1 October 2026», «امروز» / «دیروز» (Today / Yesterday) in lists, numeric «۱۴۰۵/۰۷/۰۹» / «2026/10/01» only in dense tables. Month and weekday names are written out in `src/constants/calendar.ts`, not taken from Intl. The month grid starts the week and tints the weekend per calendar (see [languages](languages-and-currency.md)). `AmountField` takes and returns the stored integer (rials or cents); `Calendar` and `DatePicker` take and return ISO date strings.
- **Copy:** every string the user sees comes from the messages (see [conventions](../conventions.md)). Calm and short in both languages. No emoji. Claude is written «Claude», in Latin.
  - Persian: polite plural. Buttons are verbs that name the outcome («ثبت هزینه», never «تأیید»); cancel is always «انصراف». Labels are nouns without a colon. Errors are one specific sentence ending with a period, no exclamation mark. Toasts confirm in past tense and offer «واگرد» after add/delete.
  - English: sentence case. Buttons are verbs that name the outcome («Add expense», never «OK»); cancel is always «Cancel». Labels are nouns without a colon. Errors are one specific sentence ending with a period, no exclamation mark. Toasts confirm in past tense («Transaction added») and offer «Undo» after add/delete. Use typographic apostrophes («Couldn’t»).
- **Toasts** (`Toast`, `useToast()` in `src/components/ui/toast`): stacked like a deck (newest in front, 3 at most), spread out and paused on hover or focus, swiped away toward the start edge or down, and always auto-closing: 4 s, errors 6 s, with an action («واگرد» / «Undo») 8 s.
- **Motion:** `--ease-out` for nearly everything, `--ease-lift` only for things that pop (checkbox tick, switch thumb, dialog and toast entry). 120ms color, 180ms position, 260ms overlays. Everything collapses under `prefers-reduced-motion` (in `base.css`).
- **Icons:** lucide-react, sized with `--icon-size-*` tokens. Import the `*Icon` export (`WalletIcon`, not `Wallet`).
- **Breakpoints:** 480 / 768 / 1024 (`--small-phone`, `--mobile` below 768, `--tablet-up`, `--desktop`), plus `--short-screen` (height below 600px: on phones, the keyboard is open; the login page uses `interactive-widget=resizes-content` so the keyboard shrinks the layout). Below 768 is the phone layout: taller controls (40/48/52px), 44px tap targets, bottom sheets instead of dialogs. `@custom-media` rules in `src/styles/media.css`, injected into every CSS file by PostCSS (`@csstools/postcss-global-data` + `postcss-custom-media`), as in `orange`. JavaScript uses the same values from `src/constants/media.ts`.
- **Skeletons** (#15): a page's skeleton (`…Skeleton` next to the page component, shown by its `loading.tsx` and while its own navigation runs) mirrors the real page at every width, so nothing moves when the content arrives. Build it from the real parts: the real `PageHeader`, `Card`s, titles, labels, column heads and buttons (static text needs no placeholder; buttons that can't work yet are `disabled`, controls inside `inert` sections), the same CSS classes for rows and grids, and placeholders only where data goes. `Skeleton variant="text"` is exactly one line of the surrounding font tall (`1lh`), so put it inside an element with the real text's font; `radius` matches a tile's corners (don't override its class: CSS Module order isn't guaranteed); `SkeletonWords` lays out hidden words so a placeholder wraps like a known sentence. Shared parts have their own skeletons: `CategoryChipSkeleton`, `ProgressBarSkeleton`, `BarListSkeleton`, `ColumnChartSkeleton`, `MonthSwitcherSkeleton`, `TransactionListSkeleton`, `ReportCardSkeleton`, `PageLoadingStatus` (the screen reader's «در حال بارگذاری»). Placeholders have no text baseline: a flex row aligned on `baseline` gets `align-items: center` in its skeleton. Role-dependent controls follow `useShellCanWrite()` (the shell's add form is on only for editors and admins). Data that doesn't need the database is real: the settings sections (inert, empty), the connector's address, steps and examples (`getMcpResourceUrl()` in its `loading.tsx`), the export and import cards (inert, empty book). The dashboard and the settings page sit in route groups (`(dashboard)`, `settings/(overview)`) because Next.js shows the first `loading.tsx` under the segments that change: a `settings/loading.tsx` would also cover `/settings/connector`. `html` keeps the scrollbar's room (`scrollbar-gutter: stable`), so a short skeleton replaced by a long page doesn't shift sideways. Check a skeleton against its page's story at phone, tablet and desktop widths (each page has a `Loading` story; the dashboard, budgets, accounts and categories also `LoadingViewer`; `withAddTransaction` in `src/components/add-transaction/sample-shell.tsx` turns the shell's add form on).
- **Pending states:** nothing the user starts may go quiet. A button that starts a request takes `loading` (spinner, `aria-busy`, disabled but focusable) from a `useTransition` or a busy flag until the request ends, and a request followed by navigation keeps it until the new page replaces the old one (login, setup). Row menus that run an action are disabled while it saves (`busy`). Navigation: use `Link` from `src/components/ui/link`, never `next/link` directly. It reports to `NavigationProgress` (a 3px bar along the top edge, in `AppShell`; shown after 150 ms, ends when the path or search params change, gives up after 15 s; the store is `src/components/navigation-progress/store.ts`), and a `Button` with `href` shows a spinner while its page loads. Code that calls `router.push` inside a transition passes that transition's pending flag to `useReportNavigation`, as the transactions, budgets and reports pages do (their skeleton covers the list meanwhile).
- **Accessibility:** WCAG AA contrast in both themes, visible keyboard focus, respect `prefers-reduced-motion`, correct `lang` and `dir` (set `lang` on text in the other language, like the language switch).
